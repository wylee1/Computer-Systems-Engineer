컴퓨터와 수의 표현
  - 기원 : 인류의 첫 계산 도구는 손가락으로 10진수 사용의 유력한 이유
  - 어원 : 함께 계산한다는 라틴어 computare에서 유래
  - 비트 : 전기 신호의 온/오프를 나타내는 최소 단위 (전구 하나가 1비트를 표현)
    N개의 비트는 2^N개의 정보 표현 가능
  - 진법 : 수를 셀 때 자릿수가 올라가는 단위를 기준(2진수, 8진수, 10진수, 16진수 등등)
    2진수를 8진수와 16진수로 변환이 편리하다.
  - 보수 : 컴퓨터에서 뺄셈을 덧셈으로 처리하기 위해 사용되는 개념
    r의 보수(기수 보수) : 해당진수의 보수
    r-1의 보수(감소된 기수 보수) : 해당진수 - 1의 보수
    - 1의 보수 : 모든 비트를 0은 1로 1은 0으로 반전
    - 2의 보수 : 1의 보수를 취한 후 최하위 비트에 1을 더함
    -> 뺄셈을 덧셈으로 변환하여 처리 할때 사용
  
  - 부호화된 2진수 (고정소수점)
    가장 왼쪽 비트를 부호 비트로 사용  (0 - 음수  /  1 - 양수)
    나머지 비트를 숫자의 크기로 표현
  - 부호화된 1의 보수
    부호 비트 외의 나머지 비트에 1의 보수를 취함
    문제점 : -0과 +0이 존재하여 덧셈 뺄셈 시 carry가 발생하면 부호가 바뀌는 End-Around carry가 
            발생할 수 있어 추가 연산 처리 필요
  - 부호화된 2의 보수
    부호비트 외의 나머지 비트에 2의 보수를 취함 -> 0이 하나만 존재하며, 표현 가능한 음수의 범위가
                                                1의 보수보다 하나 커 연산이 효율적이다.
- 부동 소수점 표현 : 실수를 표현하는 방식으로 비트 낭비를 줄이고 넓은 범위의 수를 표현
  - 구성 요소 
    부호 : 숫자의 양수/음수를 나타내는 비트
    지수 : 소수점의 위치를 나타내는 부분
    가수 : 숫자의 유효 자릿수를 나타내는 부분
    ex : (-1)^부호 * 10^지수 * 0.가수 | (-1)^1*10^2*0.12345
  - 정규화 : 가수의 최상위 비트가 0이 아닌 형태로 표현하는 과정 이진수에서는 항상 1.XXX형태
  - 부동 소수점 연산과정
    1. 제로 여부 확인
    2. 부호 결정
    3. 지수 및 가수 조정 (정규화 깨질 수 있음)
    4. 지수 연산
    5. 가수 연산
    6. 결과 정규화

2진 코드
  - BCD코드 : 10진수 한 자리를 2진수 4비트로 표현
  - 가중치 코드 : 각 비트가 고유한 가중치를 가짐
  - 자기 보수 코드 : 10진수의 9의보수를 0과 1을 서로 바꿔서 구할 수 있는 코드
  - 초과 코드 : 특정 값을 더하여 표현하는 코드

10진수 표현 방식
  - 팩 10진 형식 : BCD코드를 사용하여 두 자리 10진수를 8비트로 표현, 최하위 4비트는 부호(1100:양수, 1101:음수)
                 예 : 52 -> 0101 0010 1100 -> 52C
  - 언팩 10진 형식 : 10진수 한 자리를 8비트로 표현. 상위 4비트는 1111로 고정하고 하위 4비트는 BCD 코드로 숫자를 표현 최하위의 존영역은 부호를 나타냄
                 예 : 728 -> 1111 0111 1111 0010 1101 1000 -> F7 F2 D8
  - 그레이 코드 : 인접한 숫자들의 비트가 항상 1비트만 변화하도록 만든 코드 (예시 찾아보기)
                 -> 전기적 신호로 변경할 때 여러개가 변경되면 빠르게 전기적 신호가 들어와 문제가 생길 수 있음
                 그러한 전파 지연 등으로 인한 오류를 방지하기 위해 사용
                 추가적으로 그레이 코드 자체로는 연산이 불가능해서 2진수로 변환 후 연산 하고 다시 그레이 코드로 변환
  - 2진수와 그레이 코드 변환
    - 2진수 -> 그레이코드 : 최상위 비트는 그대로, 이후는 왼쪽 비트와 XOR 연산
    - 그레이코드 -> 2진수 : 최상위 비트는 그대로, 이후는 개로 얻은 2진수 비트와 XOR 연산
  
- 오류 검출 코드 : 데이터 전송 중 발생할 수 있는 오류를 검출하기 위한 코드  
- 패리티 코드 : 데이터 비트에 1비트의 패리티 비트를 추가하여 전체 1의 개수를 짝수 또는 홀수로 만듬
                예 : ASCII 7비트 + 1비트(패리티 비트) -> 단점 : 2개 이상의 비트 오류 발생 시 검출 불가
- 투 아웃 오브 파이브 코드 : 5비트 중 항상 2개의 1만 존재하는 코드 (00011 ~ 11000)
- 바이퀸 코든 : 7비트 중 항상 2개의 1만 존재하는 코드 (0100001 ~ 1010000)
- 링 카운터 코드 : 10비트 중 항상 1개의 1만 존재하는 코드 (0000000001 ~ 1000000000)
- 해밍 코드 : 오류 검출 및 정정이 가능한 코드 
   - 최대 2비트 오류 감지, 1비트 오류 정정 가능
   - 데이터 비트(D)와 체크 비트(P)로 구성  -> 체크 비트는 2^n번째 비트위치(1,2,4,8,16······)
   - 체크 비트 생성 : 특정 위치의 데이터 비트들과 XOR 연산을 통해 패리티를 맞춤
   - 오류 정정 : 체크 비트의 패리티 검사 결과가 1이면 오류 발생을 의미,
                오류가 발생한 체크 비트들의 위치를 이진수로 합산하여 오류 발생 비트 위치를 찾아 정정
                PPDPDDD ->.P는 페크 비트로 1,2,4 D는 데이터 비트로 나머지 빈공간에 들어감
                패리티비트 연산 예시 사진 확인 (1101이라는 데이터를 넣어서 각 줄에서 1의 합계는 짝수여야 함)
                정정 예시 1011001 이라는 비트 -> P1 : 1_1_0_1, P2 : _01__01, P3 : ___1001
                P1만 1의 합이 짝수가 아니기에 P1에 오류가 있다는 걸 알 수 있고, 0011001로 정정해야 한다.

디지털 논리 게이트 및 불 대수
- 디지털 논리 게이트 : 디지털 회로의 기본 구성 요소
  - AND(), OR, NOT, NAND(AND의 반대), NOR, XOR, XNOR
- 불 대수 : 논리 연산을 수학적으로 표현하고 분석하는 시스템. 논리 게이트의 동작을 식으로 표현
  - 교환 법칙, 결합 법칙, 분배 법칙, 드 모르간의 정리[ (X+Y)'= X'·Y', (X·Y)' = X'+Y' ], 이중 부정

조합 논리 회로
- 조합 논리 회로 : 현재의 입력 값에 의해서만 출력 값이 결정되는 회로, 메모리 없음
- 가산기 : 2진수 덧셈을 수행하는 회로
- 반가산기 : 1비트 2진수 두 개를 더하여 합과 올림수를 출력
            합 : S = X와 Y의 XOR연산,  올림수 : C = X와 Y의 AND연산
- 전가산기 : 1비트 2진수 두 개와 하위 비트에서 올라온 올림수를 더하여 합과 올림수를 출력
            구성 : 일반적으로 2개의 반가산기와 1개의 OR 게이트로 구성
- 병렬 가감산기 : 여러 비트의 덧셈 또는 뺄셈을 동시에 처리할 수 있는 회로, 전가산기를 병렬로 연결하여 구성
                제어신호 : 뎃셈과 뺄셈 모드를 전환하는 제어신호 존재
- 디코더 : N개의 2진 입력 정보를 최대 2^N개의 고유한 출력 중 하나로 변환하는 회로 (2to4디코더)
- 멀티플렉서 : 여러 개의 입력 선 중 하나를 선택하여 하나의 출력 선으로 보내는 회로 (데이터 셀렉터)
- 선택 선 : N개의 선택 선은 2^N개의 입력 선 중 하나를 선택할 수 있음
- 디멀티플렉서 : 하나의 입력 선을 여러 개의 출력 선 중 하나로 보내는 회로, 멀티플렉서의 반대 동작

순서 논리 회로
- 순서 논리 회로 : 현재 입력 + 과거 상태에 따라 출력 값이 결정되는 회로, 메모리 요소 포함
- 동기식 순서 회로 : 클럭 신호가 발생할 때만 상태가 변하고 출력을 내보냄(클럭 동기화)
- 비동기식 순서 회로 : 입력 신호의 변화 즉시 출력을 내보냄 (클럭 비동기)
- 일반적인 동작 원리 : 입력 -> 조합 회로 -> 플립플롭 -> 클럭 -> 출력 -> 다시 조합 회로 입력으로 피드백
- 래치 : 가장 기본적인 1비트 저장회로, 클럭없이 입력에 즉시 반응하는 경우가 많음
  - SR 래치 : 두 개의 입력을 받아 상태를 설정 하거나 초기화
      S=1 : Q=1, R=1 : Q=0  |  S=0,R=0 : 이전 상태 유지  |  S=1, R=1 : 정의되지 않은 상태 (사용 금지)
  - D 래치 : SR 래치의 단점을 보완. 하나의 데이터 입력을 받아 클럭 신호에 따라 입력 값을 저장
      D=1 : Q=1, D=0 : Q=0  |  투명성 래치 : 클럭이 활성화된 동안 입력D가 출력 Q로 그대로 전달됨
- 플립플롭 : 1비트의 2진 정보를 저장하는 클럭 동기식 순서 회로  
  ->  세트 : 플립플롭 = 1 | 리셋 : 플립플롭 = 0  |  토글 : 현재 출력을 반전시킴
  - 마스터 - 슬레이브 플립플롭 : 딜레이 래치를 2개 연결하여 레이스 현상을 방지하고 안정적인 동작을 보장
  - JK 플립플롭 : 세트, 리셋, 토글을 모두 수행할 수 있는 다용도 플립플롭
  - T 플립플롭 : JK 플립플롭을 변형하여 만든 것으로 토글 기능에 특화 ( T = 0 : 이전상태 유지 | T = 1 : 토글)

프로세서와 명령 실행 제어 개요
- 컴퓨터 구조 : 앨런 튜링의 튜링 머신과 폰 노이만의 컴퓨터 구조를 기반으로 발전
- 튜링 머신 : 하드와이어드 방식으로 하드웨어적 설계를 통해 프로세서를 제어하는 방식
- 폰 노이만 구조 : 마이크로프로그래밍 방식으로 코드를 통해 프로세서를 제어하는 방식으로 마이크로 명령어 사용

마이크로프로세서와 CPU

- CPU(중앙처리장치)
  - 제어장치, 연산장치, 레지스터, 

마이크로 명령어

- F1,F2,F3(3비트) : 마이크로 오퍼레이션 필드로 다양한 연산 명령어

- BR(2비트) : 분기 필드로, 점프, 호출, 복귀 등의 분기 명령어
- AD(7비트) : 주소 필드로 연산이나 분기에 필요한 주소 정보를 포함

논리 연산 명령어의 동작 명칭
- AND : 마스크 동작

- XOR : 비교 동작

주소 수에 따른 명령어 형식
- 명령어 형식 : OP 코드 뒤에 오퍼랜드가 오는 기본 구조를 가짐
- 오퍼랜드 : 명령어의 연산 대상이 되는 데이터 또는 주소
- 오퍼랜드 갯수에 따른 분류
  - 3주소 명령어 : 오퍼랜드 3개 (R1=A+B) -> 한번의 명령으로 레지스터 간 또는 레지스터와 메모리간 연산이 가능
    장점 : 프로그램 길이가 짧아 실행 속도가 빠름 | 단점 : 명령어 길이가 길어져 하드웨어 설계가 복잡
  - 2주소 명령어 : 오퍼랜드 2개 (R1=R1+B) -> 한개의 오퍼랜드가 결과를 저장하는 역할도 수행함
    장점 : 3주소 명령어보다 하드웨어 설계가 간단 | 단점 : 연산을 위해 여러 명령어가 사용되어 프로그램 길이가 길어짐
  - 1주소 명령어 : 오퍼랜드가 1개 (ADD B | AC=AC+B) -> 누산기를 필수로 사용
    장점 : 명령어 형식이 간단하고 디코딩이 쉽다 | 단점 : 모든 연산이 누산기를 거쳐야 하므로 병목 현상이 발생
  - 0주소 명령어 : 오퍼랜드가 0개 (PUSH, POP) -> 스택을 필수로 사용
    장점 : 명령어 길이가 매우 짧고, 스택기반 연산에 효율적 | 스택을 활용해야 하므로 연산 과정이 다소 복잡
  
주소 지정 방식 (12회차 23분 50초 예시 보면서 대입해보기)
- 명령어의 오퍼랜드 필드에 있는 주소 정보를 실제 데이터가 있는 메모리 주소(유효주소)로 변환하는 방법
  - 직접 주소 : 오퍼랜드 필드의 주소가 실제 데이터의 주소
  - 즉시 주소 : 오퍼랜드 필드의 값이 실제 데이터 값
  - 간접 주소 : 오퍼랜드 필드의 주소가 실제 데이터 주소를 담고 있는 메모리의 주소
  - 상대 주소 : 프로그램 카운터 값에 오퍼랜드 필드의 변위를 더하여 유효 주소를 계산(PC+Offset)
  - 인덱스 주소 : 인덱스 레지스터 값에 오퍼랜드 필드의 주소를 더하여 유효 주소를 계산(XR+Address)
  - 레지스터 주소 : 오퍼랜드 필드가 레지스터 번호를 직접 명시하며, 실제 데이터는 해당 레지스터에 있음
  - 레지스터 간접 주소 : 오퍼랜드 필드가 레지스터 번호를 명시하며, 해당 레지스터에 실제 데이터의 주소가 저장되어 있음

CISC vs RISC
- CISC : 복잡 명령어 집합 컴퓨터
  - 특징 : 많은 구의 명령어, 복잡한 동작을 수행하는 명령어, 모든 주소 지정 모드 지원,
          가변 길이 명령어 형식, 메모리에서 피연산자 처리, 마이크로 프로그램 제어 방식 채택
  - 장점 : 고급 언어로 알고리즘 표현 용이, 프로그램 길이 짧음
  - 단점 : 명령어 수가 많아 하드웨어 복잡, 실행 빈도 낮은 명령어가 자원 낭비
- RISC : 간략 명령어 집합 컴퓨터
  - 특징 : 적은 수의 명령어, 간단하고 고정된 길이의 명령어 형식, 로드와 스토어 명령어로만 메모리 접근 제한,
          모든 동작은 CPU 레지스터 내에서 수행, 하드와이어드 제어 방식 채택
  - 장점 : 하드웨어 설계 단순, 빠른 디코딩 및 실행 속도, 병렬 처리 용이
  - 단점 : 프로그램 길이가 길어질 수 있음
- 요약 : CISC는 고급 언어 표현에 유리하지만, 하드웨어가 복잡해지고 비효율적인 명령어도 포함될 수 있다.
         RISC는 하드웨어 설계가 단순하고 빠르지만, 복잡한 기능을 구현할 때 여러 명령어를 조합해야 할 수 있다.

레지스터
- CPU 내부에 위치한 고속의 임시 기억 장치로, 연산에 필요한 데이터를 저장하고 전송하는 기능
- N비트 레지스터는 N개의 플립플롭과 조합 회로로 구성됨
주요 레지스터 종류
- AC : 누산기, 연산 결과를 임시 저장
- PC : 프로그램 카운터, 다음에 실행할 명령어의 주소를 저장
- MAR : 메모리 주소 레지스터, 접근할 메모리의 주소를 저장
- MBR : 메모리 버퍼 레지스터, 메모리에서 읽거나 쓸 데이터를 임시 저장
- IR : 명령어 레지스터, 현재 실행 중인 명령어를 저장
- DR : 데이터 레지스터, 데이터 및 피 연선자 임시 저장
- TR : 임시 레지스터, 임시 데이터를 저장
- INPR : 입력 레지스터, 외부 장치로부터 입력된 정보를 저장
- OUTR : 출력 레지스터, 외부 장치로 출력할 정보를 저장
레지스터 분류 (어셈블리어 기준)
- 세그먼트 레지스터 : 일반 응용 프로그램은 직접 접근 불가하며, OS나 어셈블러 등에서 사용
- 인덱스 레지스터 : 주소 계산 시 사용되는 기준점 역할
- 플래그 레지스터(상태 레지스터) : 연산 결과나 CPU의 현재 상태를 나타탬, 제어 장치와 밀접한 관련
- 범용 레지스터 : 데이터 저장 및 다양한 연산에 사용
- PSW : 프로그램 상태 워드로 상태를 나타내는 레지스터

레지스터 전송 언어(RTL)
- RTL : 레지스터 간 마이크로 연산 전송을 간결하고 명료하게 표시하기 위한 기호 언어
- 문자 : 레지스터 이름을 나타냄
- 괄호 : 레지스터의 특정 비트나 메모리 부분을 나타냄
- 화살표 : 데이터 전송을 나타냄
- 콤마 : 두 개 이상의 마이크로 오퍼레이션이 동시에 수행될 때 사용
- 제어 함수 : [ P : R2 <- R1 ] 조건 P가 참일 때 수행, P자리에는 클록 신호가 자주 사용됨
레지스터 전송 방식
1. 직렬 전송 
  - 특징 : 하나의 클록 펄스 동안 하나의 비트만 전송, 여러 비트가 순차적으로 전송되어 워드를 구성
  - 장점 : 결선 수가 적어 하드웨어 구성이 간단
  - 단점 : 느리다.
2. 병렬 전송
  - 특징 : 하나의 클록 펄스 동안 레지스터 내 모든 비트(워드)가 동시에 전송
  - 장점 : 직렬 전송보다 빠름
  - 단점 : 데이터 비트 수만큼 결선이 필요하여 하드웨어 구성이 복잡
3. 버스 전송
  - 특징 : 여러 레지스터가 하나의 공통된 전송 통로를 공유하여 데이터를 전송
  - 장점 : 병렬보다 결선 수가 적음 (하나의 공통된 선을 사용하므로)
  - 단점 : 한 번에 하나의 레지스터만 버스를 사용할 수 있어 동시 전송은 불가능

마이크로 오퍼레이션과 사이클 타임
- 마이크로 오퍼레이션(MO) : 마이크로 명령어를 구성하는 클록 펄스 동안 수행되는 기본적인 동작 단위
- 명령어 : 여러 마이크로 오퍼레이션의 집합
- ADD : 피연산자 가져오기, 더하기, 저장 등의 MO로 구성
- STA : 누산기의 내용을 메모리에 저장 
- LDA : 메모리에서 데이터를 가져와 누산기에 로드
- 마이크로 사이클 타임 : 하나의 마이크로 오퍼레이션을 수행하는데 필요한 시간
- 동기 고정식
  - 특징 : 모든 MO 중 수행 시간이 가장 긴 MO의 사이클 타임을 CPU 클록 주기로 설정
  - 장점 : 제어가 간단
  - 단점 : 수행 시간 차이가 클 경우 효율이 저하되고 자원 낭비가 발생
- 동기 가변식
  - 특징 : 수행 시간이 유사한 것끼리 집합을 만들고, 집합마다 서로 다른 사이클 타임 정의
  - 장점 : 수행시간 차이가 큰 경우 효율적이고, 처리 시간당 처리 효율이 높아짐
  - 단점 : 제어가 복잡하며, 사이클 타임이 정수배가 되도록 해야함

명령어 실행 상태
- CPU의 주요 실행 상태 : 무엇을 하고 있는지 나타내는 4가지 상태
1. Fetch (인출) 상태 : 다음에 실행할 명령어의 주소를 PC로부터 가져와 명령어 레지스터에 로드하고 디코딩
              다음 상태 : 직접 주소인 경우 Execute 상태, 간접 주소인 경우 Indirect 상태
2. Indirect (간점) 상태 : 명령어가 간접 주소를 포함하는 경우 해당 주소를 통해, 유효 주소를 찾아옴
              다음 상태 : 유효 주소를 찾으면 Execute 상태
3. Execute (실행) 상태 : 명령어 레지스터의 명령어를 해독하고 실제 연산을 수행
              다음 상태 : 명령어 실행이 완료되면 Fetch 상태, 인터럽트 발생 시 Interrupt 상태로 전이
4. Interrupt (인터럽트) 상태 : 실행 중인 작업을 중단하고, 특정 사건을 처리하기 위해 인터럽트 서비스 루팅으로 이동,
                              이때 현재 프로그램의 복귀 주소를 저장
              다음 상태 : ISR 실행이 완료되면 Fetch로 돌아가 중단되었던 다음 명령어 처리
상태 전이 흐름 : Fetch → (Indirect) → Execute → (Interrupt) → Fetch

기억장치 
- 정보를 받아들여 저장하고 필요할 때 다시 사용할 수 있게 해주는 장치로 다량의 이진 정보를 저잘할 수 있는 셀들의 집합
- 폰 노이만 구조에서 메모리 유닛 부분을 의미
- RAM, ROM, 휘발성 메모리, 비휘발성 메모리, 파괴적 기억장치, 비파괴적 기억장치

ROM의 종류
1. ROM      : 한 번 형태가 만들어지면 전원이 꺼져도 정보는 장치 내에 보존 
2. Mask Rom : 한 번 만들어진 내용은 바꿀 수 없고, 대량 주문시 경제적(반도체 회사에서 제작)
3. PROM     : 사용자가 한 번 프로그래밍할 수 있는 ROM으로 높은 전압 펄스로 회로를 끊는 방식으로 프로그래밍
4. EPROM    : 특수 자외선을 이용하여 내용을 초기로 되돌릴 수 있는 PROM
5. EEPROM   : 전기 신호로 내용을 지울 수 있는 PROM (EPROM -> 자외선, EEPROM -> 전기 신호)
6. PLD      : 프로그래밍 가능한 논리 장치, AND 및 OR 배열을 포함하여 프로그램 가능한 게이트
              디코더를 포함하여 N개의 입력으로 2^N이하의 출력을 만들 수 있음
  6-1. PROM : AND 배열 고정, OR 배열만 프로그래밍 가능
  6-2. PAL  : AND 배열 프로그래밍 가능 OR 배열 고정
  6-3. PLA  : AND, OR 배열 모두 프로그래밍 가능
7. SPLD     : 플립플롭이 포함되 순차적 처리가 가능한 PLD
8. CPLD     : 여러 개별 PLD가 하나의 직접 회로 위에 집합된 복잡한 구조
9. FPGA     : 사용자가 직접 프로그램할 수 있는 VLSI 배열회로

기억장치 용량 계산
- 메모리 용향 : 워드의 개수 * 워드당 비트 수
- K : 주소 라인의 수
- M : 데이터 라인의 수
- 어드레스 라인 개수 계산 : 2^K = 총 워드 개수를 만족하는 K를 찾는다.
  1024 워드는 주소 라인 10개가 필요
- 핀 수 계산 : 주소 라인 핀 수 + 데이터 라인 핀 수 + 제어 신호 핀 수

메모리 계층 구조
- 기억장치들은 CPU와의 거리, 속도, 용량, 가격에 따라 계층적으로 구성
- CPU와 가까울수록 : 속도가 빠르고, 용량이 작으며, 가격이 비쌈
- CPU와 멀어질수록 : 속도가 느리고, 용량이 크며, 가격이 저렴함
- 계층 순서(CPU와 멀어지는 순서)
  1. 레지스터 : CPU 내부에 있어 가장 빠르고 작은 기억장치
  2. 캐시 메모리 : CPU와 주기억장치 사이에 위치하며, 자주 사용하는 데이터를 임시 저장하여 속도차이 완화
  3. 주기억장치 : RAM을 주로 사용하며, CPU가 직접 접근하여 프로그램과 데이터를 저장
  4. 보조기억장치 : 하드디스크, SSD등 데이터를 영구적으로 저장 (입출력 프로세서를 통해 주기억장치와 소통)

주기억장치 및 보조기억장치
  주기억장치
   - 대부분 RAM으로 구성(일부 ROM)
   - RAM은 변경 가능한 프로그램이나 데이터를 저장하며, ROM은 불변하는 상주 프로그램을 저장
   - 부트스트랩 로더 : ROM 부분에 저장되며, 전원이 켜질 때 컴퓨터 소프트웨어를 가동시키는 역할 (BIOS)
   - 데이터 대역폭 : 단위 시간당 전송할 수 있는 정보량을 의미하며, 컴퓨터의 비트 수로 표현
  보조기억장치 (HDD, SSD, 자기 테이프, 블루레이 등)
   - 다량의 정보를 영구적으로 저장하고 보관하기 위한 장치
   - 주기억장치의 내용을 영구적으로 저장 및 보관하는데 사용
     - 블루레이 : 청자색 레이저를 사용해 데이터를 읽고, 섹터 기반 비디오 포맷을 사용(약 25GB저장 가능)
     - SSD : 반도체를 이용해 정보를 저장하고, 기계적 지연 시간이 없어 압도적으로 빠름
       - 셀 당 비트 저장량에 따른 분류
         1. SLC : 한 셀에 1비트 저장 (수명 가장 길고 빠름)
         2. MLC : 한 셀에 2비트 저장
         3. TLC : 한 셀에 3비트 저장
         4. QLC : 한 셀에 4비트 저장 (용량 크고 저렴하지만 수명 짧음)

연관 메모리
 - 내용 지정 메모리(CAM)으로 불리기도 하며, 일반적으로 메모리의 주소가 아닌 데이터 내용 자체로 정보를 탐색하고 접근하는 메모리
 - 데이터 내용으로 탐색하여 병렬 탐색이 가능하여 속도가 매우 빠름
 - 각 셀에 저장 능력뿐만 아니라 외부 입력과 내용을 비교하기 위한 논리회로를 포함하므로 일반 RAM보다 비쌈
 - 주로 캐시 메모리에 사용되어 빠른 속도 제공
 - 주어진 키와 일치하는 데이터를 모든 워드에서 병렬적으로 찾아냄

캐시 메모리
 - 주기억장치와 프로세서 논리 회로 간의 속도 차이를 줄이기 위해 사용되는 고속 메모리, 자주 참조되는 데이터를 임시로 저장하여 시스템 성능을 높임
 - CPU의 기본 동작
   1. CPU는 필요한 데이터를 캐시에서 먼저 탐색
   2. 히트 : 데이터를 찾으면 바로 가져와 사용
   3. 미스 : 데이터가 없으면 주기억장치에서 데이터를 찾아 가져옴(이때 주기억장치에서 가져온 데이터는 캐시에도 복사됨)
   히트율 : 캐시 메모리의 성능을 나타내는 지표로, "히트 횟수 / (히트 횟수 + 미스 횟수)" 로 계산
 - 참조의 국부성 : 프로그램 실행 시 특정 지역의 데이터를 참조하는 경향을 의미, 캐시 메모리는 이 특성을 활용해 자주 사용되는 데이터를 미리 가져옴
   - 시간 국부성 : 최근 참조된 데이터는 가까운 시링에 다시 참조될 가능성 높음
   - 공간 국부성 : 최근 참조된 데이터 근처의 데이터에서 참조될 가능성 높음
 - 캐시 사상 방식(mapping 매핑) : 주기억장치 데이터를 캐시로 가져올 때 캐시의 어느 블록에 저장할지 결정하는 방식 (연관, 직접, 세트 연관 사상 등)
 - 기록 방식 : CPU가 캐시의 데이터를 변경할 때 주기억장치에 어떻게 반영할지 결정하는 방식
 - write-through : 캐시와 주기억장치 동시에 갱신 (일관성은 유지되나 속도가 느릴 수 있음)
 - write-back : 캐시를 먼저 갱신한 후 해당 블록이 교체될 때 주기억장치에 갱신 내용을 반영 (속도는 빠르지만, 일관성의 문제가 있음)
 - write-once : 일반적으로 위 두가지 방식의 절충 형태로 사용됨

 가상 메모리
 - 보조기억장치의 총량에 해당하는 거대한 기억장소를 갖고 있는 것처럼 프로그램을 짤 수 있도록 하는 개념(실제 장치 용량의 한계를 극복하기 위해 사용)
 - 보조기억장치의 일부를 마치 주기억장치처럼 사용, 속도는 느려지지만 프로그램 실행 가능성을 높임
 - 용어 정리
   - 주소 공간 : 가상 주소들의 집합으로, 보조기억장치에서 마치 주기억장치인 것처럼 사용되는 공간을 의미
   - 메모리 공간 : 실제 주기억장치의 주소들이 기억 장소로 표현된 집합
   - 논리 주소 : 가상 메모리에서 지정되는 주소(실제 주소와 다름), 세그먼트 번호, 페이지 번호, 워드 번호로 구성
   - 페이지 : 가상 주소 공간과 물리 메모리 공간을 나누는 고정된 크기의 블록 단위
   - 세그먼트 : 논리적으로 연관된 명령어나 데이터 집합으로 크기가 가변적
   - MMU : 메모리 관리 장치
     - 역할 : 논리 주소를 물리 주소로 변환, 종적 저장 장소 재배치, 다른 사용자가 하나의 프로그램을 같이 사용하기 위한 편의 제공
             , 허락되지 않은 메모리 접근 방지, 사용자가 OS 기능을 변경하지 못하도록 하는 정보 보호

입출력 주변 장치 및 전송 방식
- 일반적인 입출력 구조 : 프로세서 - I/O 버스 - 인터페이스 - 주변 장치
- 데이터, 주소, 제어 버스 : 각각 데이터 전송, 주소 지정, 제어 신호 전송
- 비동기 데이터 전송 방식 : CPU와 주변 장치 간 속도 차이가 크기 때문에 대부분 비동기 방식으로 데이터를 전송
  - 스트로브 펄스 방식 
    - 유닛이 데이터를 버스에 올리고 스트로브 신호를 보내면 목적지 유닛이 데이터를 수신
    - 피드백이 없어 데이터 수신 여부를 알 수 없음
  - 핸드셰이킹 방식
    - 데이터 전송에 대한 응답 신호를 주고받음, 데이터를 버스에 올리고 "데이터 유효" 신호를 보냄, 데이터를 수신하고 "데이터 수신 확인" 신호를 보냄
- 하드디스크 인터페이스 : IDE, SATA, SCSI, SAS

입출력 전송 모드 및 DMA
- 프로그램 제어 I/O : CPU가 주변 장치를 끊임 없이 감시하며 데이터 전송, CPU 시간 낭비
- 인터럽트에 의한 I/O : CPU가 다른 작업 수행하다가 인터럽트 요청이 오면 해당 작업을 중단하고 I/O 전송을 수행, CPU 시간 낭비 줄임
- DMA 
  - DMA Burst Mode : DMA 제어기가 메모리 버스를 독점하여 여러 워드로 구성된 블록을 지속적으로 전송 (고속 장치에 사용)
  - Cycle Stealing Mode : DMA 제이거기 한 번에 한 워드의 데이터 전송 후 제어권을 CPU에 반환, CPU는 DMA 전송을 위해 동작에 대한 지연이 거의 없으며, 
                          한 번의 메모리 사이클만 DMA에 빼앗김
  - 기본 요소
    - 주소 레지스터 : 데이터가 저장되거나 전송될 메모리 블록의 시작 주소 저장
    - 워드 카운터 레지스터 : 전송할 워드의 개수 저장
    - 제어 레지스터 : 읽기/쓰기 모드 등 전송 모드 지정

채널
- 데이터 채널 또는 입출력 프로세서라고도 불리며, 입출력 장치와 직접 통신하여 CPU의 부하를 줄이는 전용 프로세서
- 입출력을 분리하여 독립적으로 처리하는 별도의 프로세서
- 기능
  1. 여러 블록 입출력 처리 가능
  2. 입출력 처리 능력을 향상
  3. 멀티플렉서 채널은 여러 장치의 입출력을 동시에 제어하는데 적합
  4. CPU에 지속적인 개입이 필요 없음
  5. 채널 커맨드 워드(CCW) : IOP가 메모리로부터 가져오는 명령어로 코멘트 코드, 데이터 주소, 플래그, 카운터 등으로 구성됨

인터럽트
- CPU가 실행 중인 작업을 잠시 중단하고, 특정 이벤트 를 처리한 후 다시 원래 작업으로 복귀할 수 있도록 하는 메커니즘
- (원인에 따른)분류
  - 외부 인터럽트 : 시스템 외부 요인에 의해 발생 (입출력 장치, 타이밍 장치 시간 초과, 전원 이상)
  - 내부 인터럽트 : 프로그램 내의 잘못된 명령이나 데이터에 의해 발생 '트랩'이라고도 불림
  - 소프트웨어 인터럽트 : 프로그램의 요청에 의해 의도적으로 발생
- 분기 주소 결정 방법
  - 벡터 인터럽트 : 인터럽트 발생 원인에 따라 특정 주소로 분기하여 해당 서비스 루틴을 실행
  - 비벡터 인터럽트 : 인터럽트 발생 시 고정된 하나의 주소로만 분기하여, 소프트웨어적으로 인터럽트 원인을 파악한 후 해당 서비스 루틴을 찾아감
- 인터럽트 발생 시 스택에 저장되는 정보
  - PC(프로그램 카운터) 내용 : 다음 명령어 주소, 인터럽트 처리 후 원래 프로그램으로 복귀하기 위해 저장
  - 상태 레지스터 내용 : CPU 현재 상태 정보
  - CPU 레지스터 내용 : 작업 중이던 CPU 내부 레지스터들의 값
  - 우선순위 인터럽트 : 동시에 여러 개의 인터럽트 발생 시 어떤 인터럽트 먼저 처리할지 결정하는 시스템
  - 폴링 방식 : 소프트웨어에 의한 우선순위 결정, CPU가 순차적으로 검사하여 처리, 처리/반응 시간이 느려질 수 있음
  - 하드웨어에 의한 우선순위 결정
    - 데이터 체인 : 모든 인터럽트 장치들이 직렬로 연결되어 우선순위가 높은 장치부터 요청을 처리
    - 병렬 우선순위 인터럽트 : 각 장치에 개별적으로 우선순위가 부여되어 병렬적으로 처리
