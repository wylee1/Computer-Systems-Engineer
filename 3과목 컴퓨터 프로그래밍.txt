프로그램
- 프로그램 : 처리 방법과 순서를 기술한 명령문의 집합
- 소프트웨어 : 프로그램과 동의어로 사용
- 시스템 프로그램 : 컴퓨터의 운영을 담당
- 응용 프로그램 : 시스템 프로그램을 제외한 모든 프로그램
- 프로그래밍 : 프로그램을 만드는 행위
- 코딩 : 프로그래밍과 유사하지만, 코드를 작성하는 행위만을 지칭
- 프로그래밍 언어 : 수행하고자 하는 바를 전달하기 위한 표기법
- 고급 언어 : 자연어에 가까운 형태로 작성되어 사람이 이해하기 쉬운 언어
- 저급 언어 : 기계어에 가까워 사람이 이해하기 어려운 언어
- 주요 프로그래밍 언어 
  - 포트란 : 과학 기술 계산을 목적으로 개발된 최초의 고급언어
  - 코볼 : 사무 처리용 목적으로 개발된 언어
  - 베이직 : CUI 시스템으로 구현된 최초의 언어
  - C언어 : 시스템 소프트웨어 개발에 적합하며 이식성이 높고 범용적인 언어
  - 기계어
    - 0과 1의 2진수로 표현되는 언어
    - 가장 저급 언어
    - 하드웨어에 의존적이므로 호환성이 없음
    - 직접 이해하므로 번역 과정 없이 처리 속도가 가장 빠름
    - 기계 중심 언어
- 프로그램 작성 과정
  - 문제 분석 -> 알고리즘 분석 -> 순서도 작성 -> 프로그램 설계 및 작성 -> 코딩 및 디버깅 -> 문서화

언어 구문 형식
- 구문 형식 : 프로그래밍 언어의 구문을 체계적이고 효율적으로 기술하는 방법
- BNF : 언어 구문을 형식적으로 정의하는 가장 보편적인 방법
- EBNF : BNF를 확장하여 더 간결하고 읽기 쉽게 표현할 수 있도록 함
- 메타 기호 (::=, |, <>, {}, [])
- 파스 트리
  - 특정 표현식이 주어진 BNF 문법에 따라 오바르게 구성되었는지 확인하기 위해, BNF를 이용하여 대상 표현식을 뿌리로 하고 터미널 노드들을 왼쪽에서 오른쪽으로 나열하는 방식으로 생성되는 트리
  - 작성된 표현식이 BNF 정의에 따라 올바르게 작성되었는지 검증하는 데 사용

프로그래밍 언어 구현 기법
- 번역 기법 : 고급 프로그래밍 언어로 작성된 원시 프로그램을 컴퓨터의 기계어로 변환하여 실행시키는 방법
- 번역기 : 원시 언어를 읽어들여 목적 언어로 된 기능이 동등한 프로그램을 출력해주는 언어 처리기
- 컴파일러 : 원시 코드를 목적 코드로 번역하여 실행
- 어셈블러 : 어셈블리어를 기계어로 번역
- 링커 : 재배치 가능한 기계어 형태의 여러 프로그램을 묶어서 실행 가능한 기계어로 번역
- 로더 : 기계 프로그램을 실제 실행 가능한 기계어로 변환하여 주기억장치에 적재하고 실행을 시작하는 서비스 프로그램 (메모리 할당, 연결, 재배치, 적재)
- 프리프로세서 : 원시 언어와 목적 언어가 모두 고급 언어인 경우 사용
- 프로그래밍 언어 수행 순서 
  소스 코드 -> 컴파일러를 통한 번역 -> 목적 코드 생성 -> 링커가 여러 목적 코드를 묶음 -> 로드 모듈 생성 -> 로더가 로드 모듈을 주 메모리에 적재 -> 프로그램 실행

로더의 종류 및 기억 장소 할당
- 로더 : 주기억장치로부터 정보들을 주기억장치로 옮기기 위해 메모리 할당, 연결, 재배치, 적재를 담당하는 서비스 프로그램
- 종류
  - 절대 로더 : 가장 간단한 로더  |  목적 프로그램을 입력받아 프로그래머가 지정한 주소에 그대로 적재  |  직접 지정해 유연성이 떨어지지만, 구현이 쉽다.
  - 컴파일 즉시 로더 : 번역기가 로더의 역할을 담당해 컴파일 후 즉시 실행  |   프로그램 크기가 크고 한 언어로만 작성된 프로그램에 적합
  - 재배치 로더 : 주기억장치의 상태에 따라 목적 프로그램을 주기억장치에 적재할 수 있도록 함  |  프로그램 실행 시 실제 메모리 주소가 결정 됨
  - 링킹 로더 : 여러 부 프로그램이 변경되어도 다른 모듈을 다시 번역할 필요 없이, 프로그램에 대한 기억 장소 할당과 부 프로그램의 연결을 자동으로 수행
- 기억 장소 할당
  - 정적 기억 장소 할당 : 실행 전 모든 변수의 크기와 위치가 고정적으로 결정됨  |  주로 포트란 언어에서 사용
  - 동적 기억 장소 할당 : 실행 중에 필요한 만큼 메모리 공간을 할당
    - 컴파일러 기법 사용 : 스택 기반 할당으로 함수의 호출, 지역 변수 저장 등에 사용되며 LIFO 구조를 가짐, 속도가 빠름
    - 인터프리터 기법 사용 : 힙 기반 할당으로 프로그래머가 명시적으로 요청하여 할당 및 해제하는 메모리 영역으로, 유연하지만 스택보다 속도가 느릴 수 있음

객체 지향 프로그래밍
- 사물이나 개념을 속성과 기능을 가지는 개체로 모델링하여 프로그래밍하는 기밥
- 클래스와 객체를 중심으로 프로그램을 개발하며, 데이터와 데이터를 처리하는 함수를 하나로 묶는 방식
-                    구조적 프로그래밍            vs         객체 지향 프로그래밍
  데이터 처리  : 데이터와 함수를 이용한 순차적 구현  |  변수와 기능을 객체라는 개념으로 묶음
  유지보수     : 상대적으로 어려움(대규모 프로젝트)  |  객체 추가 시 기존 객체와 무관, 용이함
  프로젝트 규모 :   소규모 프로젝트에 적합          |       대규모 프로젝트 진행에 적합
  개발 단위    :          함수 중심                |   새로운 개념의 모듈 단위, 객체 중심

객체 지향 언어의 주요 특징
1. 추상화 : 객체의 성질을 분해하고, 공통된 성질을 추출하여 슈퍼 클래스를 설정하는 것, 객체들의 불필요한 세부 사항은 숨기고, 핵심 정보만 단순하게 표현
2. 캡슐화 : 객체 내에서 데이터와 함수를 하나로 묶는 것, 사용자는 기능만 알고 사용하며 어떻게 처리되는지 알 필요가 없도록 은폐
3. 정보 은폐 : 다른 객체에게 내부 정보를 숨기고, 특정 메소드를 통해서만 접근을 허용, 부작용을 최소화 해 모듈 간 독립성을 높임, 객체간 결합도를 낮추고 재사용성을 높이며 인터페이스를 단순화함
4. 상속성 : 서브 클래스의 객체가 슈퍼 클래스의 모든 속성과 메소드를 물려받는 것, 서브는 상속 외에 새로운 것을 추가하여 사용 가능, 객체와 클래스의 재사용성을 증대
5. 다형성 : 같은 상위 객체(클래스)에서 상속받은 여러 하위 객체들이 다른 형태의 특성을 갖는 객체로 이용될 수 있는 성질, 하나의 메소드나 클래스가 상황에 따라 다른 방식으로 동작

객체 지향 설계 방법론
- 설계 방법론 : 객체 지향 시스템을 효과적으로 설계하기 위한 체계적인 접근 방식
- 럼바우 기법
  1. 객체 모델링 : 정적이고 구조적인 측면을 다룸, 객체 다이어그램을 생성
  2. 동적 모델링 : 시간에 따른 객체들의 상호작용과 상태 변화를 다룸, 상태 다이어그램을 생성
  3. 기능 모델링 : 데이터의 흐름과 변환 과정을 다룸, 자료 흐름도를 생성

C 언어 개요 및 특징
- 특징 : 시스템 프로그래밍 적합, 컴파일 기법 사용, 높은 이식성, 구조화 언어, 다양한 연산자 제공, 포인터 사용 가능

예약어 : 시스템이 알고 있는 특수한 기능을 수행하도록 이미 용도가 정해진 키워드, 변수 이름이나 다른 목적으로 사용 불가
식별자 : 사용자가 직접 정의하여 사용하는 단위, 변수(함수) 이름 등으로 사용 (첫글자는 숫자로 할 수 없음, 대소문자 구별)

기억 클래스 : 변수의 생존 기간과 유효 범위를 결정하는 키워드
- 주요 기억 클래스
  1. auto (자동 변수) : 함수 진입 시 생성, 함수 탈출 시 소멸, 선언된 함수 내부에서만 유효, 대부분의 지역 변수는 auto로 선언(키워드 생략 가능)
  2. static (정적 변수) : 프로그램 시작부터 종료까지, 선언된 함수 내부에서만 유효 (전역변수 인 경우 해당 파일 내에서만 유효), 초기화 한 번만 수행하며 종료시 까지 유지
  3. extern (외부 변수) : 프로그램 시작부터 종료까지, 전체 프로그램에 걸쳐 사용 가능, 다른 파일에 정의된 변수를 참조할 때 사용, 실제 변수는 다른 파일에 선언
  4. register (레지스터 변수) : 함수 내에서만 존재, CPU 블록 내부에서만 유효, 레지스터에 저장하도록 요청, 고속 연산이 필요한 변수에 사용

구조체(Structure)와 공용체(Union)
- 구조체 : 서로 다른 자료형을 하나의 묶음으로 정의하여 새로운 자료형을 만드는 방법 
        struct 구조체 이름 { 자료형 멤버변수1;   자료형 멤버변수2;};
  - 모든 멤버 변수가 고유한 메모리 공간을 가지고, 구조체변수.멤버이름 또는 포인터변수->멤버이름 으로 접근한다.
- 공용체 : 서로 다른 자료형을 하나의 묶음으로 정의하지만 동일한 메모리 공간을 공유
        union 공용체이름{ 자료형 멤버변수1;   자료형 멤버변수2;};
  - 가장 큰 크기의 멤버 변수만큼 메모리 할당, 한 번에 하나의 멤버만 값을 가짐, 메모리 절역이 중요하거나 모든 멤버의 값을 동시 사용하지 않을 때 사용
열거형(Enum) : 관련 있는 정수형 상수들의 목록에 이름을 부여하여 정의하는 자료형
  - 가독성을 높이고 오류를 줄임
        enum 열거형이름 { 상수1, 상수2=값, 상수3};
  - 기본값은 0 이며, 특정값을 지정가능하고 값 지정이 없는 경우 +1로 계산

어셈블리어
- 프로그램의 기호화된 명령 및 주소를 사용
- 작성된 CPU마다 어셈블리어가 다를 수 있어 호환성이 없다.
- 메모리를 직접 제어할 수 있다.
- 오류 검증이 어렵고 디버깅이 어려움, 프로그래밍 시간이 오래 걸림

어셈블리어 문법
- CPU 제조사마다 문법과 명령어에 차이가 있음
- 구성 : 연산코드, 피연산자, 주석
- 필드 구성
  1. 라벨 필드 : 코드의 특정 위치를 식별하는 이름
  2. 명령어 필드 : 프로그램 동작을 정의하는 부분 (메모리 참조, 참조가 아닌 명령어, 어셈블리에게 지시하는 명령어)
  3. 코멘트 필드 : 코드 설명을 위한 부분

레지스터
- CPU 내부에 위치한 초고속 저장 공간
- 주요 레지스터 종류
  1. 세그먼트 레지스터 : 프로그램의 각 부분이 메모리 어디에 시작하는지 주소를 저장
  2. 인덱스 레지스터 : 배열이나 스택의 특정 위치를 가리키는 주소를 저장
  3. 플래그 레지스터 : 결과에 대한 상태 정보를 비트 형태로 저장
  4. 범용 레지스터 : 직접 연산을 수행하거나 데이터를 임시 저장하는 레지스터

슈도 명령어
- 원시 프로그램을 번역할 때 어셈블러에게 요구되는 동작을 지시하는 명령어

어셈블리어 명령어
- 니모닉 코드 자체의 의미와 직접 연결되어 기억하기 쉬움

어셈블러 주소 지정 방식
- CPU가 명령어의 피연산자에 접근하기 위해 주소를 계산하는 방식
  1. 즉치 주소 지정 모드 : 명령어 자체에 데이터 값이 직접 포함되어 있는 방식
  2. 레지스터 주소 지정 모드 : 피연산자가 CPU 레지스터에 저장되어 있는 방식
  3. 직접 주소 지정 모드 : 피연산자의 실제 메모리 주소가 명령어에 직접 지정되는 방식
  4. 간접 메모리 주소 지정 모드 : 피연산자의 메모리 주소가 레지스터에 저장되어 있고, 그 레지스터가 가리키는 주소로 접근하는 방식
