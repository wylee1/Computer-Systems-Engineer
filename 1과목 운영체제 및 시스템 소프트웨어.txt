전조기 4과목
1. 운영체제
OS - 운영체제
4가지 구성요소의 구성도
사용자 - 응용프로그램 - 운영체제 - 컴퓨터 하드웨어

운영체제란 하드웨어를 관리하는 소프트웨어로 사용자와 하드웨어 사이에 중재자 역할
목적 (성능평가 요인)
1. 처리능력 향상 (Throughput)
2. 반환시간 최소화 (response time, turn around time)
3. 사용 가능도 향상 (availability) 가용성 - 한정된 자원을 요구할 때 신속하고 충분히 지원해 줄 수 있는지의 정도
4. 신뢰도 향상 (reliability) - 주어진 문제를 얼마나 정확하게 해결할 수 있는지

운영체제 처리방식 (아래로 내려가는 순서대로 나온 방식)
1. 일괄처리 - 작업을 일정 기간, 일정량이 될 때 까지 모았다가 한번에 처리하는 방식
2. 다중 프로그래밍 - 여러개의 프로그램이 동시에 실행되는 것처럼 처리하는 방식 (하나가 사용하다가 입출력장치와 같이 CPU를 필요로 하지 않는 작업을 할때 다른 프로그램이 사용)
3. 다중처리 - 2개 이상의 프로세서로 구성되어 다중 작업을 구현하는 방식
4. 시분할 - 한 컴퓨터를 동시에 이용할 수 있게 하기 위해 사용자들에게 CPU에 대한 일정 시간을 제공하여 프로그램을 수행
5. 실시간 처리 - 처리를 요구하는 자료가 발생할 때마다 즉시 처리하여 응답
6. 다중모드처리 - 한시스템에서 여러가지 모드를 제공
7. 분산 처리 - 네트워크를 통해 여러 컴퓨터 시스템에 작업과 자원을 나누어 처리하게 하는 방식 

운영체제 서비스
프로그램 실행, 입출력 연산, 파일 시스템, 통신, 자원 할당, 회계(로그인, 사용량), 오류탐지, 보호와 보안

자원 관리자 관점
제어 프로그램이다.
CPU시간, 메모리 공간, 저장장치 공간, 입출력 장치 등
자원 상태 확인 -> 계획 -> 할당 -> 회수

시스템 소프트웨어 (제어프로그램, 처리프로그램)
응용 소프트웨어를 실행하기 위한 플랫폼을 제공하고 컴퓨터 하드웨어를 동작, 접근할 수 있도록 설계된 컴퓨터 소프트웨어
제어 프로그램 (감시, 작업 관리, 데이터 관리)
처리 프로그램 (언어 번역, 서비스, 문제처리)

    CPU 스케줄링 정보(우선순위)0
thread(스레드) [단일 스레드와 다중 스레드]
CPU이용의 기본 단위 -> 동기적(motivation)
    - 스레드는 프로세스의 자원과 메모리를 공유 -> 자원 공유
    - 다중 프로세스 구조에서 각 스레드는 다른 프로세스에서 병렬로 실행 -> 경제성
    - 성능과 처리율을 향상시킬 수 있다. -> 응답성
    - 프로세스들 간의 통신을 향상
    - 스레드는 동일 프로세스 환경에서 서로 다른 독립적인 다중 수행이 가능 -> 적응성

사용자 모드 & 커널 모드
    - 커널은 운영체제의 핵심이 되는 프로그램으로 시스템의 모든 것을 통제
    - 사용자 및 응용프로그램은 시스템콜을 통해 접근에 접근할 수 있음
    (사용자모드)사용자 프로세서 -> (사용자모드)시스템 콜 호출 -> (커널모드)시스템 콜 실행 -> (사용자모드)시스템 콜에서 복귀
    사용자 수준 스레드의 장단점
    - 장점                          - 단점
    1. 이식성이 높음                 1. 시스템의 동시성을 지원하지 않음
    2. 오버레드가 적음               2. 확장에 제역이 따름
    3. 유연한 스케줄링이 가능         3. 스레드 간 보호 불가능
    사용자 수준에서 지원되는 스레드가 커널에서 지원되는 스레드에 비해 가지는 장점
    1. 스레드 간의 전이 시 커널이 개입하지 않아 수행이 빠름
    2. 운영체제를 호출 -> 커널에서 지원되는 스레드
    3. 스레드의 개수와는 처리시간을 많이 배정 받을 수 있다 -> 배정과 스레드 갯수는 무관
    4. 
커널모드 (슈퍼바이저 모드, 시스템 모드, 특권 모드) 

Concurrent process(협력적 프로세스, 병행 프로세스)
    시스템 내에서 실행중인 다른 프로세스의 영향을 주거나 받는 프로세스
    협력을 허용하는 이유
      1. 정보공유
      2. 계산 가속화
      3. 모듈성
    IPC(프로세스 간 통신)기법
    1. 공유 메모리(Shared memory)
      -> 공유하는 데이터를 공유 메모리에 둠
    2. 메시지 패싱(Message passing)
      -> 공유하는 데이터를 커널에 둠
    여기서 공유하는 부분을 임계구역이라고 한다.
    
    임계구역
    - 적어도 하나 이상의 다른 프로세스와 공유하는 데이터에 접근하고 갱신할 수 있는 구역
    임계구역 문제
    1. 상호 배제
    - 한 프로세스가 임계구역에서 실행되면, 다른 프로세스들은 그 임계구역에서 실행될 수 없다
    2. 진행
    - 임계구역에서 실행되는 프로세스가 없고, 진입하려는 프로세스들이 있다면, 다른 구역에서 실행중이지 않은 프로세스만 진입할 수 있는지 결정하는데 참여할 수 있다.
    (즉 계속 진행되고 있어야 한다.)
    3. 한정된 대기 (제한 대기. 한계 대기)
    - 임계구역에 진입 후 다른 프로세스들이 진입하는 허용 횟수는 제한되어야 함
    해결안 = 동기화 구현 기법

동기화 구현기법 (임계구역 문제의 해결안)
  1. 데커알고리즘 (두개의 프로세스로 한정)
  2. 피터슨 알고리즘 (두개의 프로세스로 한정)
  3. 상호배제
    - 임계구역 들어가기 전에 반드시 lock(락)하고 나올때는 반드시 반환해야한다. 스핀락(spinlock)
  4. 세마포어
    - 다익스트라가 제안
    - 원자적 연산(P와 V)으로만 접근
    - 세마포어(S)는 음이 아닌 정수값을 갖는 플래그 변수(S의 초기 값은 임계구역에 접근할 수 있는 프로세스의 갯수)
    (임계구역 문제의 해결안으로 나온 기법이기에 프로세스 하나가 세마포어 값을 수정할 때 다른 프로세스가 같은 세마포어 값을 동시에 수정할 수 없다.)
  5. 모니터
    - 객체지향 기반의 고급언어로 구현된다.
    - 자료 추상화와 캡슐화의 정보은폐 성질을 이용하여 상호배제의 목적을 이루어낸다.
    - 공유데이터, 연산들, 초기화 코드로 이루어져있음
    - 진입큐에 따라서 공유 데이터에 접근함
    - 외부에서 데이터에 직접 엑세스 하는 것이 아님
  [1~4 -> busy wating = while문과 같이 loop문을 돌면서 확인하는 기법으로 리소스 낭비가 있다.]

교착상태 (Deadlock)
  - 프로세스 집합내의 모든 프로세스가 다른 프로세스에 의해서만 일어날 수 있는 이벤트를 기다리는 상황
  - 필요조건 4가지
    1. 상호배제
    2. 점유하며 대기
    3. 비선점
    4. 순환 대기
교착상태 처리 방법
  1. 교착상태 예방
    - 필요조건 중 적어도 하나가 성립하지 않도록 보장하는 방법 (이용률이 저하되고, 처리율이 감소함)
  2. 교착상태 회피
    - 평생 요구하고 사용할 자원에 대한 부가적인 정보를 미리 제공할 것을 요구 (자원할당그래프 알고리즘, 은행원 알고리즘 등)
    - 은행원 알고리즘
      은행에 적용시 고객들이 현금을 찾으러 와도 일정한 순서에 의해 모든 고객의 요청을 다 들어줄 수 있게 된다.
  3. 교착상태 탐지
    - 교착상태에 있는 프로세스를 발견하는 방법
  4. 교착상태로부터 회복
    - 모두 중지하거나, 하나씩 중지
    - 자원을 회수 ( 희생자 선택, 후퇴, 기아 상태를 고려)
    교착상태가 없어질 때까지 프로세스를 하나씩 중지시키는 것이지 자원을 하나씩 비선점시키는 것이 아님

스케줄링
  - 준비 큐에서 대기 프로세스를 선택하고 CPU를 할당하는 작업
  - 디스패치에 의해 선택된 프로세스에 CPU가 할당된다.
  스캐줄링 기준 = 목적
    1. CPU 이용률 - 40~90%범위를 가짐
    2. 처리량 - 단위 시간당 완료된 프로세스의 개수가 많아야 한다.
    3. 총처리 시간 - 제출 시간과 완료시간의 간격
    4. 대기 시간 - 준비 큐에서 대기하면서 보낸 시간의 합
    5. 응답 시간 - 하나의 요구를 제출한 후 첫 번째 응답이 나올 때 까지의 시간
  선점·비선점 스케줄링
    CPU 스케줄링 결정을 해야하는 4가지 상황
    1. 프로세스가 실행에서 대기로 전환될 때
    2. 프로세스가 실행에서 준비완료로 전환될 때
    3. 프로세스가 대기에서 준비완료로 전환될 때
    4. 프로세스가 종료할 때
  비선점 스케줄링
    - FCFS 
      CPU를 먼저 요청하는 프로세스가 CPU를 먼저 할당 받는다.(선입선출큐로 관리)
    - SJF
      작업시간이 짧은 프로세스 먼저 할당 받는다.
  선점 스케줄링
    - RR
      FCFS 스케줄링과 유사하지만 시스템이 프로레스 사이를 옮겨 다니도록 선점이 추가된다. (문맥교환)
      시간할당량 또는 타임슬라이스라고 하는 단위의 시간을 정의 (시분할 시스템)
    - HRN = (대기시간+실행시간)/실행시간  ->  값이 높을 수록 우선순위 높음
      대기시간과 실행시간을 이용하여 우선순위를 정하는 방식
    - SRT
  우선순위 스케줄링 (SJF, HRN)
    - 우선순위가 프로세스에 연관되어 있으며, CPU는 우선순위가 높은 프로세스에 할당됨
  우선순위 스케줄링 문제점
    - 무한봉쇄 또는 기아상태
      실행준비는 되어 있으나 CPU할당을 받지 못하고 무한히 대기하는 경우
    해결방안
      1. aging(노화)
        - 오랫동안 대기하는 프로세스들의 우선순위를 점진적으로 증가
      2. 라운드 로빈과 우선순위 스케줄링을 결합하는 방법
  다단계 큐 스케줄링
    - FIFO와 RR 스케줄링 방식을 혼합한 것으로 상위 단계에서 완료되지 못한 작업은 하위 단계로 전달되어 마지막 단계에서는 RR방식 사용
  다단계 피드백 큐 
    - 프로세스가 큐들 사이를 이동하는 것을 허용함

주기억장치(Main Memory) - 메인 메모리는 형대 컴퓨터 시스템의 운영에 중심적인 역할을 한다.

동적 메모리 할당
  - 가변 파티션 기법 : 프로세스를 메모리의 가변 크기 파티션 기법에 할당하는 가장 간단한 방법 중 하나
    ex : 가변 분할 기억장치 할당, 세그먼테이션
    Hole : 사용가능한 메모리 블록
  - 연속 메모리 할당 기법
    1. First-fit (최초 적합)
     - 첫 번째 사용 가능한 가용 공간을 할당
    2. Best-fit (최적 적합)
     - 사용가능 공간 중 가장 작은 것을 택
     - 아주 작은 가용공간을 만들어 낸다.
    3. Worst-fit (최악 적합)
     - 가장 큰 가용 공간을 택
     - 가용공간이 충분히 커서 다른 프로세스를 위해 유용하게 사용 가능

단편화 (Fragmentation)
 - 외부 단편화 (가변파티션에서 발생)
  -> 유효 공간들을 합치면 충분한 공간이 되지만, 작은 조각들로 분산되어 사용할 수 없는 상황
  - 50%의 규칙 : 최초 적합의 경우 통계적으로 N개의 블록이 할당되었을 때 0.5N개의 블록이 외부단편화 때문에 손실됨
    (즉 메모리의 3분의 1이 쓸 수 없게 된다.)
 - 내부 단편화 (고정파티션에서 발생)
  -> 고정분할 기억장치 할당에서 분할되어 할당된 크기와 프로세스의 크기 사이의 남는 부분 (사용할 수 없는 부분)
 - 외부 단편화 해결
   - 압축(compaction)[재배치기법] 
     - 메모리 모든 내용을 한군데로 몰고 모든 가용 공간을 다른 한군데로 몰아서 큰 블록을 만드는 것이다. 
     - 재배치가 어셈블 또는 적재시에 정적으로 행해진다면, 압축은 실행될 수 없다. -> 직접주소지정방식으로 배치한 경우 압축할 수 없다.

페이징(Paging)
  - 연속 메모리 할당을 괴롭히는 두 가지 문제인 외부 단편화와 관련 압축의 필요성을 피한다.
    - 논리주소에서 페이지 번호는 페이지 테이블의 번호로 이동해 저장되어 있는 물리주소를 넘기고 페이지 오프셋은 물리주소의 페이지 오프셋으로 넘어간다.
    - 물리주소에서 프레임은 모두 크기가 동일한 정적할당으로 되어있다.
    - 논리 주소를 물리 주소로 변환하는 과정 -> 매핑(mapping)한다고 한다.

가상메모리(Virtual Memory)
  - 프로세스 전체가 메모리 내에 올라오지 않더라도 실행이 가능하도록 하는 기법이다.
  - 주요 장점 중 하나는 사용자 프로그램이 물리 메모리보다 커져도 된다는 점이다.
  - 가상메모리에 해당하는 부분을 물리메모리에서 가져와야 하는데 가상 메모리가 물리 메모리보다 크기 때문에 페이지가 없을 수 있다.
    이때 백업 저장장치에서 가져와야 하는데 이것을 "페이지 폴트"(page fault)라고 한다.

  - 페이지 교체(page Replacement) = 페이지 대치
    - 페이지 폴트시 비어 있는 프레임이 없을 때 페이지 교체를 실행
    - 희생될 프레임을 선정해 교체 알고리즘을 가동 
      1.FIFO : 메모리에 올라온지 가장 오래된 페이지를 내쫓는다.
      2.OPT : 앞으로 가장 오랫동안 사용되지 않을 페이지를 찾아 교체한다.
      3.LRU : 가장 오랫동안 사용되지 않은 페이지를 교체한다.
      4.NUR : 가장 사용빈도가 낮은 페이지를 교체한다.
      스레싱(Thrashing) : 반복해서 페이지 폴트가 발생으로 인한 과도한 페이징 작업 페이지 -> 부재율

워킹 셋(작업 집합)
  - 최근 N만큼의 페이지 참조를 관찰하겠다는 것
  - 한 프로세스가 최근 N번 페이지를 참조했다면 그 안에 들어있는 서로 다른 페이지들의 집합을 "작업 집합"라고 부른다.
  - 구역성(locality)을 토대로 하고 있다.
    예 : 10번의 페이지 참조를 진행했는데 그 안에 1,4,5,7이라는 페이지가 참조되었었다면, {1,4,5,7}이 워킹셋이다.
  - 구역성(지역성) : 프로세스가 실행되면서 하나의 페이지를 일정시간동안 집중적으로 액세스 하는 현상

디스크 스케줄링 
  - FCFS는 디스크 스케줄링의 가장 간단한 형태
  - SCAN은 디스크 암이 디스크의 한끝에서 시작하여 다른 끝으로 이동하며, 가는 길에 있는 요청을 모두 처리한다.
    (엘리베이터 알고리즘)
  - 예시 : 디스크 큐 : 98,183,37,122,14,124,65,67  시작위치 : 53
    FCFS는 헤드의 이동거리가 640이고, SCAN은 헤드의 이동거리가 208이다.
  - C-SCAN : 각 요청에 걸리는 시간을 좀 더 균등하게 하기 위한 SCAN의 변형이다.
    한쪽으로 헤드를 이동하면서 요청을 처리하지만, 한쪽 끝에 다다르면 반대방향으로 헤드를 이동하며 서비스를 시작하는 것이 아니라
    서비스 시작위치로 돌아가서 반대 방향으로 헤드를 이동하면서 요청을 처리한다.
    예시 : 53 -> 14로 이동하면서 요청처리, 183으로 이동 후 183 -> 65로 이동하면서 요청처리 (이동거리는 326)
    일반 SCAN은 53 -> 14는 동일 단, 14 -> 183 이기에 나중에 요청한 작업을 먼저 처리하는 방식이 됨
    문제 : 현재 위치 50, 요청 대기열 순서 : 100,180,40,120,0,130,70,80,150,200 (이동거리 380)
  - SSTF는 현재 헤드 위치에서 가장 가까운 위치의 서비스를 처리
    53 65 67 37 14 98 122 124 183 (헤드이동거리 236)
    가운데 트,랙이 안쪽이나 바깥쪽 트랙보다 서비스 받을 확률이 높다.
    헤드에서 멀리 떨어진 요청은 기아상태가 발생할 수 있다.
  - 에센바흐 : 탐색 시간 최적화 뿐만 아니라 회전 지연시간도 최적화하고자 하는 최초의 알고리즘
  - SLTF : 디스크 헤드가 특정 실린더에 도착하면 그 실린더 내의 여러 트랙에 대한 요청들을 검사한 후 
           회전지연시간이 가장 짧은 요청부터 서비스하는 알고리즘
  
파일 시스템 
  - 저장장치의 물리적 특성을 추상화하여 논리적 저장 단위, 즉 파일을 정의한다.
  - 파일을 보조저장장치에 기록된 관련 정보의 집합이다. (사용자가 보는 단위)
    - 예시 문제 : 파일에 대한 설명으로 틀린것 
      답 : 3번 (파일은 주로 주기억장치에 저장하여 사용한다.) -> 주기억장치가 아닌 보조기억장치이다.
파일 연산
  - 파일 -> 추상적인 데이터 유형
  - 운영체제는 파일에 대해 실행할 수 있는 연산을 위한 시스템 콜을 제공 
  - 7가지 연산(생성, 열기, 쓰기, 읽기, 위치 재설정, 삭제, 절단)
파일 시스템 구현
  - 운영체제를 어떻게 부트시키는지, 블록의 총수, 가용 블록의 수와 위치, 디렉토리 구조, 파일에 대한 정보
  1. 부트 제어 블록 : 운영체제를 부트 시키는데 필요한 정보를 가지고 있음
  2. 볼륨 제어 블록 : 볼륨의 블록의 수, 크기, 가용 블록의 수, 포인터 등의 정보를 가짐
  3. 디렉토리 구조  : 파일을 조직화하는데 사용된다.
  4. 파일별 FCB    : 파일에 대한 자세한 정보를 가지고 있다.
  유닉스 파일 시스템에서는 각각 부트블록, 슈퍼블록, I-NODE list, I-NODE라고 불리며
  윈도우 NT 파일시스템에서는 파티션 부트 섹터와 마스터 파일테이블(부트제어블록을 제외한 3가지)로 불린다.

FCB (파일 제어 블록)
  - 사용자 공간에서 값을 읽을 때
    보조기억장치에서 파일을 커널로 가져오고 해당 파일을 부르는 명칭이 달라진다.
    (유닉스 : 파일 디스크립터 / 윈도우 : 파일 핸들) ->  FCB와 비슷

파일 접근 방법 
  - 순차 접근 : 시간적 속도가 빠르고, 처리비용이 절감된다. / 순차적으로 실제 데이터만 저장되므로 공간의 활용률이 높다.
  - 직접 접근 : 디스크 모델에 기반함 (디스크가 파일 블록에 임의적 접근을 허용하기 때문) / 읽기나 쓰기의 순서에 제약이 없다.
  - 색인(index)을 활용 : 직접 접근 방법을 기반으로 색인을 활용

디렉터리 구조
  1. 1단계 디렉터리
    - 가장 간단한 디렉터리 구조
    - 같은 디렉터리에 있는 모든 파일이 존재함으로 유일한 이름을 가져야 함
  2. 2단계 디렉터리
    - 사용자별로 자신만의 사용자 파일 디렉터리를 가진다.
    - 비슷한 구조를 가지지만, 각 디렉터리에는 오직 한 사람의 파일만 저장
    - 사용자 작업이 시작되거나, 시스템에 로그인등을 통해 접속하면 MFD를 먼저 탐색
    - 마스터 파일 디렉터리는 사용자 이름이나 계정 번호로 색인되어 있고, 각 엔트리는 사용자의 UFD를 가르키고 있다.
  3. 트리구조 디렉터리
    - 유닉스, 윈도우, dos 등에서 사용되는 구조
    - 서브 디렉터리나 파일을 가질 수 있다.
    - 생성과 파괴가 용이하다.
    - 탐색은 포인터를 사용하며, 경로명은 절대와 상대 경로명을 사용
  4. 비순환 그래프 디렉터리
    - 부 디렉터리의 공동 사용이 가능하다.
    - 디스크 공간을 절약할 수 있다.
    - 하나의 파일이나 디렉터리가 여러 개의 경로 이름을 가질 수 있다.
    - 공유 파일 제거시 떨어진 포인터 문제가 발생할 수 있다.
    예시 : 바로가기를 만들어두고 원래 파일을 삭제
  
파일 보호
  - 파일 보호기법
    - 이름 명명 : 파일 이름을 모르는 사용자는 접근 제외
    - 패스워드 : 사용자마다 패스워드를 제공하여 패스워드를 알아야만 파일을 이용
    - 암호화 : 내용을 암호화하여 누구나 쉽게 공유하지만, 인가된 사용자만 그 내용을 파알할 수 있다.
  - 권한부여
    - ACM : 접근 권한을 행렬로써 표기한 기법
    - ACL : 객체나 개체 속성에 적용되어 있는 허가 목록

보안 기법
  - 내부보안 : 내장된 보안 기능을 이용하여 프로그램의 신뢰성 있는 운영과 데이터의 무결성 보장을 기하는 기법
  - 인증 : 합법적인 사용자에게 유·무형의 자원을 사용하도록 허용할 것인지를 확인하는 행위(패스워드, 인증용 카드, 지문 검사 등)
  - 암호화 : 1. 대칭키 : 암호화, 복호화 동일 키 사용(1개의 키 사용)      - DES, AES, SEED, ARIA, MASK 등 (E가 있으면 대칭키 [야매])
            2. 공개키 : 암호화, 복호화 다른 키 사용(안전한 키 분배 필요) - RSA, DSA 등  - 짧은 평문을 암호화 하는데 좋다

분산 시스템
  - 메모리나 클럭을 공유하지 않는 프로세서 모음
  - 통신 네트워크에 의해 상호 연결된 약결합 된 노드들의 집합
  - 분산 처리 시스템의 계층 구조
    1. 사용자 프로그램 : 프로그램에 대한 관리 기능
    2. 파일 시스템 : 파일 관리에 대한 기능
    3. 프로세스 : 프로세스 관리에 대한 기능
    4. 기억장치 : 기억장치 관리에 대한 기능
    5. 하드웨어 : 컴퓨터 시스템의 기본 기능
  - 분산 처리 시스템의 장점(목적)
    1. 자원공유
    2. 계산 속도 향상
    3. 신뢰성

네트워크 토폴로지
  - 분산 시스템은 통신 네트워크에 의해 상호 연결된 약결합 된 노드들의 집합
    1. 약 결합 시스템(독립적) - 각 사이트는 자신만의 운영체제와 저장장치를 가짐
    2. 강 결합 시스템(상호의존) - 공유 메모리 이용, 저장장치를 공유, 프로세스 간의 경쟁 최소화
  - 종류
    1. 그물형(완전연결형) - n개의 장치는 n(n-1)/2개의 채널이 필요
    2. 성형(star) - Hub라는 중앙 제어장치와 전용 점-대-점 링크
    3. 버스형(bus) - 멀티포인터 링크 구성, 전송순서를 결정, 데이터 반사를 막기위한 터미네이터 필요, 이더넷이 대표 예시
    4. 링형(ring) - 각 장치는 양쪽에 있는 장치와 전용으로 회선 구성을 이룸, 한 방향으로만 링을 따라 전송
                    , 설치와 재구성이 쉽다, 한 장치의 결함은 전체를 사용할 수 없게함
    혼합 접속형태
      - 버스와 성형을 합친 상태

네트워크 및 분산 운영체제
  - 네트워크 운영체제(약결합) - 모든 범용 운영체제 및 임베디드 운영체제가 여기에 속함
    - 적절한 시스템에 로그인(원격)하여 시스템으로 데이터를 전송하여 원격으로 자원에 액세스할 수 있는 환경 제공
    - 주요 기능
      - 원격 로그인
      - 원격 파일 전송
      - 클라우드 저장장치
  - 분산 운영체제(강결합)
    - 자원관리
    - 주요기능
      - 데이터 마이그레이션
      - 계산 마이그레이션
      - 프로세스 마이그레이션

프로세스 연결 방식
  - 시분할 공유 버스 : 하나의 통신로를 이용해 데이터 전송, 간단하고 전송률 낮음, 경제적이지만 버스에 이상이 생기면 전체 가동 불능
  - 크로스바 스위치 : 버스의 수를 기억장치의 수 만큼 증가, 모든 장치에 대한 동시전송은 가능하지만 하드웨어 복잡, 높은 전송률(프로세스 많은 경우 적합)
  - 다중포트 메모리 : 공유 버스와 크로스바 스위치 결합한 형태, 프로세서의 수가 적을경우 적합
  - 하이퍼큐브 : 상호연결망 형태로 많은 처리기를 경제적인 방법으로 연결할 수 있는 방법, 한개의 프로세서에 연결되는 수가 n개면 프로세서는 2^n개가 필요

UNIX
  - 상당 부분 C언어를 사용해 작성, 이식성 우수
  - 둘 이상의 사용자가 동시에 사용할 수 있어 정보와 유틸리티들을 공유하는 편리한 작업 환경을 제공
  - 트리 구조의 파일 시스템을 갖는다.
  - 대화식 운영체제
  - 하나 이상의 작업에 대해 백그라운드에서 수행 가능
  - 명령어
    Fork  : 프로세스 생성
    chmod : 접근 권한 설정
    chown : 파일 소유자 변경
    chgrp : 그룹 소유권 변경
    cat : 파일 내용 화면에 표시
    | : 명령의 결과를 다음 명령의 입력으로 넘김
